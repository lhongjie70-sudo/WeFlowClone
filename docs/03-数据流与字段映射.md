# 数据流与字段映射

这份文档回答一个问题：**WeFlow 里的那一条消息，最后长成了 WeClone 训练集里的哪一行？**

## 1. 全景

```
WeFlow 本机数据库
   │  (WeFlow 自己负责解密，整合层不碰)
   ▼
GET /api/v1/messages?talker=...   → 原始 JSON（localType / isSend / senderUsername ...）
   │
   ▼  weflow/schema.py: Message
   │
   ├─ mapping.type_name_for()     localType → text/image/voice/video/sticker/file/location
   ├─ mapping.extract_text()      content / parsedContent / appmsg XML → 一句人话
   ├─ mapping.format_create_time() epoch → "2024-08-16 09:00:00"
   ├─ exporter: 媒体落盘            → data/dataset/media/images/<basename>
   ▼
data/dataset/csv/<会话>/<会话>_<起>_<止>.csv
   │
   ▼  WeClone: weclone/data/qa_generator.py
dataset/res_csv/sft/chat-sft  (ShareGPT 格式)
   │
   ▼  LLaMA-Factory (LoRA)
data/model_output
```

## 2. 八个列

WeClone 的 `DataProcessor.load_file()` 用 `pandas.read_csv(encoding="utf-8")` 读入，
然后：过滤 `skip_type_list` → 用 `type_name` 分流处理 → `pd.to_datetime(CreateTime)`。

所以我们的 CSV 必须满足：

| 要求 | 实现 |
| --- | --- |
| UTF-8，可带 BOM | 写 `utf-8-sig`（Excel 打开不乱码，pandas 也能读） |
| 换行 CRLF | 与 WeFlow 原生导出一致 |
| 表头固定 8 列 | `id,MsgSvrID,type_name,is_sender,talker,msg,src,CreateTime` |
| 含逗号/引号/换行的字段 | 用 `"` 包裹，内部 `"` 双写 |
| 类型名为英文 | `text/image/voice/video/sticker/file/location`（WeClone 词典双语） |

### 2.1 `id`

会话内从 1 递增。分片后仍连续（`1..20000`、`20001..40000`）。
WeClone 不依赖它，但排查问题很方便。

### 2.2 `MsgSvrID`

取 WeFlow 的 `serverId`；为空时退回 `localId`。
客户端翻页时用它去重（WeFlow 分页边界可能重复返回同一条）。

### 2.3 `type_name`

映射表（与 WeFlow 的 `WeCloneFormatter.getWeCloneTypeName` 保持一致）：

| WeChat `localType` | `type_name` | WeClone 行为 |
| --- | --- | --- |
| 1 | `text` | 主力数据，进入 Q&A |
| 3 | `image` | 多模态微调（`include_type` 含 image 时）；找不到文件则降级为截断点 |
| 34 | `voice` | 在 `cut_type_list` 里 → 作为会话切分点 |
| 43 | `video` | 同上 |
| 47 | `sticker` | 在 `skip_type_list` → 直接丢弃 |
| 48 | `location` | skip |
| 49（appmsg，`<type>6</type>`） | `file` | skip（但文件名会保留在 `msg`） |
| 49（其它 appmsg：链接/小程序/引用） | `text` | 正文取 `title + des + url` |
| 10000 / 10002 / 42 / 50 | `unsupported` | 不写入 CSV |

> **为什么默认不写 voice/video/sticker？**
> 它们不会进入训练，只会让 CSV 变大、让 WeClone 多做一次过滤。
> 需要保留「切分点」时，把 `export.include_types` 改成
> `["text","image","file","voice","video"]` 即可。

### 2.4 `is_sender`

* API 拉取：直接用 WeFlow 的 `isSend`；
* ChatLab 导入：ChatLab 没有该字段，用 `meta.ownerId` 和 `messages[].sender` 比对；
* 都没有时默认 `0`（对方）。

WeClone 用它判断「谁在说话」：同一时间窗内 `is_sender=1` 的连续消息拼成「我的回复」，
`is_sender=0` 的拼成「对方的提问」。

**这是最容易出错的一列**：如果全是 0，`wfc prepare` 会直接报
「没有任何 is_sender=1 的消息」。

### 2.5 `talker`

发送者展示名。优先级：

```
我发出        → export.self_name（默认「我」）
对方（群聊）  → 群昵称 → 备注 → 昵称 → wxid
对方（私聊）  → 备注 → 昵称 → 会话显示名
```

WeClone 的 `_find_partner_talker()` 会用「`is_sender=0` 的 talker 是否等于文件夹名」
来推断聊天对象；私聊里只有一个对方，所以即使 talker 用的是备注（如「老张」）
而文件夹是「张三」，也能正确识别（会退化成「唯一的对方」）。

### 2.6 `msg`

见下一节。

### 2.7 `src`

* 图片：`images/<文件名>`；
* 其它媒体：`voices/…`、`videos/…`、`emojis/…`（默认不下载）；
* 文本 / 链接：空。

WeClone 的 `check_image_file_exists()` 只做一件事：
用 **basename** 去 `dataset/media/images/` 里 glob `<stem>.*`。
所以 `src` 写什么都行，**文件名必须对得上**。这也是我们把媒体统一放到
`dataset/media/images/` 的原因。

### 2.8 `CreateTime`

默认 `local`：本机时区、`YYYY-MM-DD HH:MM:SS`、不带时区。
原因：WeClone 用 `pd.to_datetime` 解析后做「时间窗口」比较（默认 2 分钟 / 5 分钟），
naive 时间最不容易踩时区坑。

想和 WeFlow 原生导出一致就改 `export.timestamp_format: "iso"`（UTC，`2024-08-16T01:00:00Z`）。

## 3. 文本抽取规则

WeClone 只训练「文本」，所以「一条消息变成什么话」直接决定数据质量。

| 消息 | `msg` 内容 |
| --- | --- |
| 普通文本 | 原文（去掉控制字符，保留换行） |
| 链接卡片 | `title + des + url`，缺哪个跳过哪个 |
| 小程序 / 视频号 | 同链接（`title` 通常就是名字） |
| 文件 | `<filename>`，没有则 `<title>` |
| 引用回复 | WeFlow 已把引用内容合并进 `content`，直接取 |
| 图片 / 语音 / 视频 / 表情 | `[图片]` `[语音]` `[视频]` `[表情]` 占位（这类消息主要由类型驱动，文本只是兜底） |
| 系统消息 | 不写入 |

空文本会被丢弃（计入 `empty_text` 跳过统计），避免产生空的 Q&A。

## 4. 目录与文件命名

```
data/dataset/csv/
└─ 张三/                                 ← 会话文件夹（display 名；可配 username）
   ├─ 张三_1_1523.csv                    ← <会话>_<起始序号>_<结束序号>.csv
   ├─ 张三_1524_30000.csv               ← 超过 max_messages_per_file 自动分片
   └─ users.json                         ← 备注 / 关系
```

* 文件夹名会做 Windows 安全化（`<>:"/\|?*` → `_`，保留名如 `CON` 前加 `_`，最长 80 字）；
* 同名会话（两个「张三」）自动加 wxid 后缀，避免互相覆盖；
* 重拉同一会话会**先删旧 CSV 再写新的**，保证一个会话一份一致数据；
* 媒体按 basename 去重，已存在就跳过下载。

### `users.json`

```json
{
  "张三": { "remark": "老张", "nickname": "张三", "username": "wxid_zhangsan" },
  "relation": "好友"
}
```

WeClone 读它来填 `QaPair.chat_with`（`_load_chat_metadata`）。
`relation` 会在 `make_dataset_args.add_relation` 为 true 时进入 system prompt。

## 5. WeClone 侧读入路径

为了让数据真的被读到，三处路径必须对齐（`wfc init` 自动处理，`wfc doctor` 会检查）：

| settings.jsonc 字段 | 值 |
| --- | --- |
| `make_dataset_args.csv_folder` | `<项目根>/data/dataset/csv` |
| `common_args.media_dir` | `<项目根>/data/dataset/media` |
| `train_sft_args.dataset_dir` | `<项目根>/data/res_csv/sft` |

`make_dataset_args.platform` 保持 `"chat"` —— 我们的 CSV 走的就是 WeClone 的
「Chat/微信」分支（与 PyWxDump 导出的结构一致）。

## 6. 导入路径（不用 API 也能用）

`wfc import` 支持三种手工导出：

| 输入 | 来源 | 处理 |
| --- | --- | --- |
| 含 8 列表头的 CSV 文件夹 | WeFlow「导出 → WeClone」 | 校验表头 → 重新编号 → 落到 `dataset/csv`，媒体按 basename 复制 |
| ChatLab JSON | WeFlow「导出 → ChatLab」或 `/api/v1/sessions/:id/messages` | `type` → `localType`，`ownerId` → `is_sender` |
| WeFlow 原始 JSON | WeFlow「导出 → JSON」 | 直接用 `localType` / `isSend` |

这让「先手工导一份、以后再换成 API 直连」成为平滑升级，而不是重做。

## 7. 已知边界

1. **群聊**：WeClone 官方建议不用群聊（多人语气混杂，模型会学串）。默认关闭，
   `wfc pull --groups` 才拉。群聊的 `talker` 依赖 WeFlow 的群昵称数据，缺了就退化成 wxid。
2. **语音转文字**：WeFlow 支持，但需要额外模型；本项目默认不开启，语音只作为切分点。
3. **撤回消息**：WeFlow 只推 `content` 摘要，本项目不重建被撤回内容，重拉时以当前库为准。
4. **表情包**：默认不下载（对模仿语气帮助很小，反而占空间）。
5. **同名会话**：自动加后缀，但显示名仍然相同，`wfc sessions` 里请以 wxid 区分。
