# 发布到 GitHub 之前

目标：**在本地把「发布」这件事完整走一遍**，确认到 GitHub 上不会出现
红灯、404、密钥泄漏、打不开的包。

一条命令：

```powershell
python scripts\release_check.py
```

它会依次检查下面 9 项，任何一项阻塞就打 `✗` 并给出处理建议。

## 1. 它会检查什么

| # | 检查 | 为什么重要 |
| --- | --- | --- |
| 1 | 版本号一致性 | `pyproject.toml` / `__init__.py` / `wfc.spec` / `build.ps1` / `build.sh` 五处必须相同，否则打出来的包版本号和仓库对不上 |
| 2 | 必要文件 | 少了 `LICENSE`、workflow、启动脚本，别人 clone 下来就跑不起来 |
| 3 | 文档链接 | README / docs 里的相对链接失效，GitHub 上点开就是 404 |
| 4 | 敏感信息 | `weflow.jsonc` 里的 Token、`data/bot/config.json` 里的 API Key、以及形如 `sk-…` 的字符串 |
| 5 | 忽略规则 | `data/`、`dist/`、`weflow.jsonc`、`vendor/WeClone/settings.jsonc` 必须被 `.gitignore` 排除 |
| 6 | workflow | `ci.yml` / `release.yml` 的 YAML 能解析、关键步骤（matrix、upload-artifact、gh-release）齐全 |
| 7 | 打包资源 | `wfc.spec` 包含网页界面、是 onedir、有 excludes、图标存在 |
| 8 | 测试 | 真的跑一遍 `unittest`，并要求 90 项以上全绿 |
| 9 | 构建产物 | `dist` 里的 exe 能执行 `version`、zip 内确实含 exe，并计算 sha256 |

附加产物（`release/`，已加入 `.gitignore`）：

```
release/RELEASE_NOTES.md   可直接贴到 GitHub Release 的说明
release/SHA256SUMS.txt     校验和
```

## 2. 三种用法

```powershell
# 日常：静态检查 + 测试 + 校验已有产物
python scripts\release_check.py

# 只想快速看静态问题（几秒钟）
python scripts\release_check.py --no-tests --no-artifacts

# 完整流程：重新构建 → 检查 → 出物料（几分钟）
python scripts\release_check.py --build
```

> `--build` 在 Windows 上调用 `packaging\build.ps1`，在 macOS/Linux 上调用
> `packaging\build.sh`。没有装好构建环境时，先跑一次构建脚本。

## 3. 本地模拟 GitHub Actions

CI 里跑的其实就是同一条命令：

```yaml
- run: python -m pip install --quiet pyyaml
- run: python scripts/release_check.py --no-artifacts
- run: python -m compileall -q weflow_clone tests scripts
```

所以 `release_check.py` 全绿 ≈ CI 会绿。运行器差异（Windows 路径、macOS 权限）
仍以 CI 为准，但常见问题（YAML 缩进、坏链接、密钥、版本漂移）本地就能拦住。

## 4. 推送到 GitHub

```powershell
# 1) 初始化（仓库已 init 且提交过就跳过）
git init
git add -A
git commit -m "feat: WeFlowClone 1.0.0"

# 2) 关联远程并推送
git remote add origin https://github.com/<你的用户名>/WeFlowClone.git
git branch -M main
git push -u origin main

# 3) 打 tag 触发三平台构建与 Release
git tag v1.0.0
git push origin v1.0.0
```

推送后：

* **Actions → CI**：三个平台各跑一次「静态检查 + 测试」；
* **Actions → Release**：`v1.0.0` 的 tag 会触发 `windows-latest` / `macos-13` / `macos-14`，
  产物自动挂到 Release 页面；
* Release 页面记得贴 `release/RELEASE_NOTES.md` 的内容（含 SHA256）。

## 5. 发布前人工确认

机械检查覆盖不到的部分：

- [ ] 用一个**干净目录**解压 zip，双击 exe，确认浏览器打开且能聊天（不要只在自己机器上试）
- [ ] 用一个真实的 API Key 跑一次「测试连接」（文档里的示例 Key 不算）
- [ ] 在**没装 Python**的电脑/虚拟机里试一次安装包
- [ ] macOS 包在真机（Intel 与 Apple Silicon 各一台）上试一次，确认右键打开可行
- [ ] Release 说明里写清「首次打开需要右键 / 更多信息 → 仍要运行」
- [ ] 确认许可与免责声明在 README、NOTICE、Release 三处都出现
- [ ] 如果仓库是公开的：确认 `vendor/WeClone` 的 AGPL 声明完整（`vendor/WeClone/LICENSE` 已在仓库内）

## 6. 常见阻塞与处理

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `版本号不一致` | 改了 `__init__.py` 忘了 `pyproject.toml` | 五处一起改（脚本会列出具体文件） |
| `文档链接失效` | 重命名了文档 | 按提示改链接，或补回文件 |
| `weflow.jsonc 里填了 access_token` | 本地调试时填过 | 清空该字段；Token 走环境变量 `WEFLOW_TOKEN` |
| `缺少 packaging/icon.ico` | 没跑过图标生成 | `python packaging/make_icons.py` |
| `没找到 dist/...` | 还没构建 | `.\packaging\build.ps1` |
| `测试 N 项`低于 90 | 新加的测试没被发现 | 确认文件在 `tests/` 且以 `test_` 开头 |
| `YAML 解析失败` | 缩进用了 Tab | 改成空格 |
