# 项目介绍

> 面向第一次听说这个项目的人：它解决什么问题、给谁用、怎么做到的、边界在哪里。
> 想让项目跑起来，看 [快速开始](02-快速开始.md)。

---

## 1. 一句话

**用微信聊天记录，造一个「像你」的数字分身。**
数据留在本机，不训练也能用；想更像，再微调。

---

## 2. 为什么会有这个项目

微信里躺着几年的对话——你和朋友的插科打诨、你和同事的工作沟通、你安慰人时的语气。
这些是训练「数字分身」最好的语料，但从「聊天记录」到「一个能聊天的模型」中间隔着一条流水线：

```
微信数据库 → 解密 → 导出 → 筛选 → 清洗 → 拼成对话对 → 微调 → 部署
```

社区里已经有两个优秀项目各管一段：

| 项目 | 负责 | 不管 |
| --- | --- | --- |
| [WeFlow](https://github.com/hicccc77/WeFlow) | 本机解密微信库、查看/导出聊天记录、本地 HTTP API、实时推送 | 不负责训练，也不规定数据给谁用 |
| [WeClone](https://github.com/xming521/WeClone) | 数据清洗、Q&A 构造、LoRA 微调、OpenAI 兼容服务 | 不负责获取数据，需要你提供规范目录的 CSV |

中间那段——**导出什么格式、放哪个目录、图片怎么对齐、备注怎么带、以后新消息怎么补**——没人管，
于是每个想试的人都要手工做一遍，还容易做错（图片路径对不上、`is_sender` 全是 0、时间格式解析失败）。

**WeFlowClone 就是这一段**，并把它做成了可重复执行的命令：

```powershell
wfc pull       # WeFlow → 标准数据集
wfc prepare    # 训练前体检
wfc train      # 微调
wfc serve      # 部署
```

## 3. 三种人怎么用它

### 3.1 只想有个「像自己」的机器人

不需要 Python、不需要显卡、不需要训练。
下载安装包 → 双击 → 浏览器打开 → 填一个 API Key → 开始聊。

背后是「人设 + 检索 + 通用大模型」：

- 从你的聊天记录统计句长、疑问比例、表情率、语气词、高频说法；
- 每次提问检索 2~3 段你以前类似场景的回答作为参考；
- 交给 DeepSeek / 通义 / Moonshot / OpenAI / 本地 Ollama 生成。

**效果预期**：语气、句长、口头禅会像；复杂推理仍然取决于你选的模型。

### 3.2 想把说话方式真正刻进模型

接上 WeFlow，拿到 API Token，然后：

```powershell
wfc pull --since 2023-01-01
wfc prepare --make-dataset
wfc train
wfc serve
```

- 7B + LoRA 约 16GB 显存；QLoRA 可降到 8GB；
- 数据量参考：1 万～5 万条开始有效果，10 万条以上更自然；
- 训练完接着 `wfc serve`，或按 WeClone 文档接微信 / Discord / Telegram。

### 3.3 想改代码 / 换数据源

整合层只有约 5000 行，纯标准库，`CONTRIBUTING.md` 里给了 6 个常见改造点：
换数据源、换模型、改人设、改界面、加命令、走训练。新增行为要有测试（当前 93 项）。

## 4. 它到底做了什么

### 4.1 数据接入

- 通过 WeFlow 的本地 HTTP API（`127.0.0.1:5031`）拉取：Token 鉴权、分页、媒体导出、SSE 实时推送；
- 也支持导入 WeFlow 的手工导出：WeClone CSV / ChatLab JSON / 原始 JSON；
- 会话筛选：按名字或 wxid、时间范围、是否含群聊、最大条数。

### 4.2 数据产出

严格按 WeClone 的约定落盘：

```
data/dataset/csv/<会话>/<会话>_<起>_<止>.csv
data/dataset/csv/<会话>/users.json
data/dataset/media/images/<文件名>
```

- 8 列 CSV：`id,MsgSvrID,type_name,is_sender,talker,msg,src,CreateTime`；
- 类型映射：`localType` → `text/image/voice/video/sticker/file/location`；
- 文本抽取：链接取标题+描述、文件取文件名、引用回复合并成一句；
- 媒体：只写 `images/<name>`，WeClone 用 basename 匹配，避免路径差异；
- 备注：写进 `users.json`，WeClone 用它填 `chat_with`；
- 分卷、去重（按 `serverId`）、重拉时原子覆盖。

字段级细节见 [03-数据流与字段映射](03-数据流与字段映射.md)。

### 4.3 训练前体检

`wfc prepare` 会检查那些「不检查就会白训几小时」的问题：

- 表头不是 8 列；`type_name` 不在 WeClone 词典里；
- 图片消息找不到媒体文件；
- `CreateTime` 解析失败；
- 会话里没有任何 `is_sender=1`（说明映射错了，无法构造 Q&A）。

每条问题都带修复建议，而不是让你去翻训练日志。

### 4.4 内置机器人

| 组件 | 实现 | 说明 |
| --- | --- | --- |
| 人设 | `bot/persona.py` | 统计 + 真实对话样例 → system prompt |
| 检索 | `bot/retriever.py` | BM25，中文字符二元组，无需分词器 |
| 模型 | `bot/llm.py` | 任意 OpenAI 兼容接口，流式 |
| 服务 | `bot/server.py` | 网页聊天 + `/v1/chat/completions` |
| 界面 | `bot/web/index.html` | 单文件、零依赖、可离线 |

不占显存、不下载权重、换模型只改三个字段。

### 4.5 持续生长

`wfc watch` 订阅 WeFlow 的 `message.new` 推送，等一个安静期后重拉变化过的会话——
保证「任何时刻数据集都是一致的」，而不是拼出一半旧一半新的 CSV。

## 5. 设计取舍

| 决策 | 原因 |
| --- | --- |
| **零改动 WeClone** | 上游升级只换目录；整合层靠 `cwd` + 绝对路径配置调用 |
| **不打包 WeFlow** | 只走公开 HTTP API，许可证边界清晰（它是 CC BY-NC-SA，禁商用） |
| **整合层零第三方依赖** | 没装 torch 也能在普通电脑上先跑通数据链路 |
| **打包用 onedir** | 免解压、启动快、杀软误报低；单文件在受限环境会启动失败 |
| **watch 全量重拉** | 追加写会让分卷命名与序号冲突；全量换一致性 |
| **默认明文存储** | WeFlow 导出是明文，首次跑通不该卡在密码流程；可自行切加密 |

架构细节见 [01-架构设计](01-架构设计.md)。

## 6. 隐私与安全

- 微信数据解密、读取、训练全部在本机；
- 人设、检索索引、API Key 只存本机（`%LOCALAPPDATA%\WeFlowClone` 或项目 `data/`）；
- 唯一的外部请求：你主动配置的模型 API，以及下载模型权重时；
- WeClone 侧默认用 Presidio 过滤电话 / 邮箱 / 证件号等，但**不保证 100%**，
  可在 `settings.jsonc` 的 `blocked_words` 里补充自己的敏感词；
- 用他人聊天记录训练或生成内容，需取得对方同意。
