# 内置机器人

用途：**不训练、不下载权重，只填一个 API Key，就得到一个「像你」的聊天机器人。**

## 1. 一次对话发生了什么

```
你发一句
   │
   ├─ 人设（persona.json）
   │    从你的聊天记录统计出来的习惯 + 几条真实对话 + 行为规则
   │
   ├─ 检索（BM25）
   │    在你历史里找 2~3 段最相似的「对方问 → 你答」
   │
   └─ system prompt + 最近 12 轮对话 + 这句话
          │
          ▼
     你配置的模型（DeepSeek / Moonshot / 通义 / OpenAI / Ollama …）
          │
          ▼
     流式逐字显示在网页里
```

只有最后一步离开本机。聊天记录、人设、索引、API Key 都在本机。

## 2. 为什么这样能「像」

通用大模型的毛病不是不会聊天，而是：**话太长、太客气、太爱总结**。
你的聊天记录恰好能纠正这三点，所以我们只提取这些：

| 提取项 | 例子 | 作用 |
| --- | --- | --- |
| 平均句长 / 短句比例 | 「平均 9 个字，68% 不超过 8 字」 | 让它别写小作文 |
| 疑问比例 | 「22% 的消息是反问」 | 学会先确认再回答 |
| 表情使用率 | 「17% 带表情」 | 该发表情时发，不该发时不发 |
| 语气词 | 「啊(43)、吧(21)、呢(9)」 | 语气自然 |
| 高频说法 | 「行吧」「我看看」「可以的」 | 有你的口头禅 |
| 真实问答 | 6 组真实对话 | 给出「具体怎么答」的锚点 |

之后每次提问再检索 2~3 组**同话题**的历史对话，作为 few-shot。
这比「请模仿我说话」这种空泛指令有效得多。

## 3. 配置项

`data/bot/config.json`（网页设置面板会写这个文件）：

| 字段 | 默认 | 建议 |
| --- | --- | --- |
| `api_base` | `https://api.deepseek.com/v1` | 任何 OpenAI 兼容地址；Ollama 是 `http://127.0.0.1:11434/v1` |
| `api_key` | 空 | 也可以设 `WFC_API_KEY` 环境变量（优先级更高） |
| `model` | `deepseek-chat` | 想更像就换更强的模型 |
| `temperature` | 0.75 | 越高越发散；冷一点更稳，热一点更"活" |
| `max_tokens` | 512 | 聊天场景不需要太长，256~512 足够 |
| `top_p` | 0.9 | 一般不动 |
| `retrieve_top_k` | 3 | 0=关闭检索；3~5 最平衡；太大容易照抄 |
| `use_persona` | true | 关掉就变成普通通用助手 |
| `bot_name` | 空（用「我」） | 想让它自称别的名字时填 |
| `extra_system` | 空 | 追加约束，例如「不要用『哈哈』」 |

环境变量：`WFC_API_KEY`、`WFC_API_BASE`、`WFC_MODEL`。

## 4. 常用命令

```powershell
wfc bot                     # 启动（默认 127.0.0.1:8765，自动开浏览器）
wfc bot --port 9000         # 换端口
wfc bot --no-browser        # 不开浏览器（服务器部署）
wfc bot --reindex           # 先重新学习聊天记录
wfc bot --api-base https://api.moonshot.cn/v1 --api-key sk-xxx --model moonshot-v1-8k
wfc bot-config              # 只看配置（Key 打码）
wfc bot-config --model deepseek-chat --bot-name 阿泽
```

> 想给局域网里的手机用：`wfc bot --host 0.0.0.0`，然后访问
> `http://<电脑IP>:8765`。注意此时同一网络的人都能访问，建议设置
> `api_key` 后不要在公共网络这样开。

## 5. OpenAI 兼容接口

内置机器人同时是一个 OpenAI 兼容服务，可以直接接第三方客户端：

```bash
curl http://127.0.0.1:8765/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"weclone","messages":[{"role":"user","content":"在吗"}],"stream":true}'
```

* `GET /v1/models` 返回当前配置的模型名；
* `POST /v1/chat/completions` 支持 `stream: true/false`；
* 人设与检索会自动注入，客户端不需要写 system prompt。

## 6. 调优经验

| 现象 | 处理 |
| --- | --- |
| 回复太长 | 降 `max_tokens`（256），并在 `extra_system` 写「最多两句话」 |
| 太客服腔 | 换更强的模型；`temperature` 提到 0.85 |
| 复读历史原句 | 降 `retrieve_top_k`（1~2），或提高 `temperature` |
| 完全不认识你 | 确认 `wfc pull` 有数据；`wfc bot --reindex` 后看界面底部「人设」计数 |
| 答非所问 | 模型能力问题；换 14B/32B 级别的 API 模型 |
| 想完全离线 | Ollama + `qwen2.5:7b`；`api_base` 填 `http://127.0.0.1:11434/v1`，`api_key` 随便填 |

## 7. 与微调的关系

| | `wfc bot` | `wfc train` |
| --- | --- | --- |
| 需要显卡 | 否 | 是（7B LoRA 约 16GB） |
| 准备时间 | 5 分钟 | 数小时 |
| 像的程度 | 语气、句长、口头禅 | 更深的表达习惯与反应方式 |
| 数据更新 | 重新 `--reindex` 即生效 | 需要重新训练 |
| 成本 | API 调用费 | 电费 + 显卡 |

推荐路径：**先用 bot 用起来**，同时用 `wfc watch` 积累数据；
数据到几万条、且对效果不满意时，再上 `wfc train`。
