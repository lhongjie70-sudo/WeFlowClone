# 与上游同步

本项目的目标之一是：**上游照常升级，整合层不跟着改**。本文说明怎么做到，以及升级步骤。

## 1. 依赖关系

| 上游 | 位置 | 耦合方式 | 升级会破坏什么 |
| --- | --- | --- | --- |
| WeClone | `vendor/WeClone`（源码，可 `pip install -e`） | 进程调用 `python -m weclone.cli`，配置 `settings.jsonc` | 配置结构（`config_version`）、CLI 子命令名、CSV 契约 |
| WeFlow | 用户自己安装的桌面应用 | HTTP API | 端点路径、字段名、鉴权头 |

## 2. 升级 WeClone

```powershell
cd vendor\WeClone
git pull                     # 如果是 git clone 下来的
cd ..\..

wfc init --force             # 重新生成 settings.jsonc（绝对路径必须更新）
.\scripts\setup.ps1 -SkipTraining
wfc doctor
```

为什么要 `wfc init --force`：WeClone 的配置项会随版本变化（`config_version`），
旧文件可能缺字段（`extra="forbid"` 会直接报错）或写入已废弃的键。

升级后建议跑一遍回归：

```powershell
wfc demo                     # 整合层自检
wfc prepare                  # 数据集校验
wfc weclone version          # 确认 WeClone 能起来
```

### 如果 WeClone 改了 CLI 子命令

`weflow_clone/pipeline/weclone.py` 里的 `make_dataset()` / `build_profile()` /
`train_sft()` / `serve()` 各对应一个子命令，改这里即可。`wfc weclone <任意命令>`
始终可用，不受影响。

### 如果 WeClone 改了 CSV 契约

改 `weflow_clone/weflow/mapping.py` 的 `CSV_HEADER` 与 `build_row()`，
再跑 `python -m unittest discover -s tests -t tests`。
测试里对表头、列序、类型名都有断言，能立刻发现不兼容。

## 3. 跟随 WeFlow

WeFlow 升级可能改 API。检查点：

1. `GET /health` 是否仍是 `{"status":"ok"}`；
2. `/api/v1/messages` 的关键字段是否还在：
   `localType`、`isSend`、`createTime`、`senderUsername`、`content`、`parsedContent`、
   `mediaLocalPath`、`mediaUrl`、`hasMore`；
3. `/api/v1/sessions` 的 `username` / `displayName` / `type`。

发现了不兼容：

* 字段改名 → 改 `weflow_clone/weflow/schema.py` 的 `from_raw()`（只改一处，全链路生效）；
* 端点改名 → 改 `weflow_clone/weflow/client.py`；
* 更彻底的变化 → 用 `wfc import`（导入 WeFlow 手工导出）作为过渡方案，
  数据管线不中断。

模拟服务 `weflow_clone/tools/mock_weflow.py` 是按 WeFlow 官方 `docs/HTTP-API.md`
实现的；如果文档更新，同步改它，测试会覆盖到。

## 4. 把 vendor 换成 submodule（可选）

如果你用 git 管理本项目，可以把 vendored 源码改成 submodule：

```powershell
rmdir /s /q vendor\WeClone
git init
git submodule add https://github.com/xming521/WeClone.git vendor/WeClone
```

然后升级就是：

```powershell
git submodule update --remote vendor/WeClone
wfc init --force
```

注意：`vendor/WeClone/settings.jsonc` 是本项目生成的（含绝对路径），
应在 `vendor/WeClone` 的 `.git/info/exclude` 里忽略，避免污染上游仓库。
