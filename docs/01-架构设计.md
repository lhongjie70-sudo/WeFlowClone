# 架构设计

## 1. 分层

```
┌──────────────────────────────────────────────────────────────────────┐
│  用户动作                                                             │
│    wfc pull / wfc prepare / wfc train / wfc serve / wfc watch          │
└───────────────────────────────┬──────────────────────────────────────┘
                                │
┌───────────────────────────────▼──────────────────────────────────────┐
│  整合层  weflow_clone                                                 │
│  ┌────────────┐  ┌──────────────┐  ┌───────────────┐  ┌────────────┐ │
│  │ cli        │  │ sync         │  │ pipeline      │  │ tools      │ │
│  │ 命令/参数   │→ │ 选会话/拉取   │→ │ 校验/调上游    │  │ 模拟服务    │ │
│  └────────────┘  └──────┬───────┘  └───────┬───────┘  └────────────┘ │
│                         │                  │                         │
│  ┌──────────────────────▼───────┐  ┌───────▼──────────────────────┐  │
│  │ weflow/                      │  │ pipeline/weclone.py          │  │
│  │ client → schema → mapping    │  │ subprocess + cwd + env       │  │
│  │        → exporter / importer │  │ （不 import 上游，解耦）       │  │
│  └──────────────┬───────────────┘  └───────────────┬──────────────┘  │
└─────────────────┼──────────────────────────────────┼─────────────────┘
                  │ HTTP 127.0.0.1:5031              │ python -m weclone.cli
┌─────────────────▼──────────────────┐  ┌────────────▼─────────────────┐
│  WeFlow（Electron，用户安装）        │  │  WeClone（vendor/WeClone）    │
│  本机微信库解密 · 实时消息 · 媒体      │  │  清洗 → Q&A → LoRA → 服务     │
└────────────────────────────────────┘  └──────────────────────────────┘
```

三个关键边界：

1. **进程边界**：整合层不 `import weclone`，只 `subprocess` 调它。
   原因：WeClone 一 import 就拉 torch / llamafactory，数据阶段完全不需要；
   而且它依赖 `cwd` 判断项目根，进程隔离最省事。
2. **协议边界**：与 WeFlow 只通过 HTTP API 说话，不读它的数据库、不装它的依赖。
3. **文件边界**：两个项目之间唯一的契约是 `dataset/csv`（8 列 CSV）+ `dataset/media`。

## 2. 一次 `wfc pull` 发生了什么

```
sessions()                      GET /api/v1/sessions
   │  按 include/exclude/--session/--groups 过滤
   ├─ contacts()                 GET /api/v1/contacts        → 备注名
   ├─ group_members()            GET /api/v1/group-members   → 群昵称（仅群聊）
   ▼
iter_messages(talker, page)     GET /api/v1/messages?offset&limit&media=1
   │  hasMore 为真就继续翻页；按 serverId 去重
   ▼
CsvExporter.export_session()
   ├─ type_name_for(localType)          localType → WeClone 类型名
   ├─ extract_text()                    文本 / 链接 / 文件 → 一句人话
   ├─ copy_or_download_media()          → data/dataset/media/images/<name>
   ├─ 写 <会话>_<起>_<止>.csv            UTF-8 BOM + CRLF，兼容 Excel 和 pandas
   └─ 写 users.json                     备注 / 关系
```

## 3. 关键设计决策

### 3.1 零改动 WeClone

WeClone 的 `cli.py` 有 `_check_project_root()`：cwd 必须有 `pyproject.toml` 且
`project.name == "WeClone"`。它还要求 `settings.jsonc` 位于包目录的上一级。

如果按「把 WeClone 代码搬进本项目」的方式整合，这两条会直接崩。
所以本项目的做法是：

* `vendor/WeClone` 保持原样（可直接 `git pull`）；
* 调用时 `cwd=vendor/WeClone`，配置用 `WECLONE_CONFIG_PATH` 指向
  `vendor/WeClone/settings.jsonc`；
* `settings.jsonc` 里所有数据路径写成**绝对路径**（`wfc init` 生成），
  这样即使 cwd 变化，数据也不会跑到别的目录。

代价：配置文件在 `vendor/WeClone/settings.jsonc` 而不是项目根。
收益：上游零侵入，升级只换目录。

### 3.2 配置分成两份，而不是一份

| 文件 | 谁读 | 为什么分开 |
| --- | --- | --- |
| `weflow.jsonc` | 整合层 | 用户日常只改这个 |
| `vendor/WeClone/settings.jsonc` | WeClone | WeClone 的 pydantic 模型多个子模型是 `extra="forbid"`，塞新段落有破坏上游 schema 的风险 |

`wfc init` 保证两者路径一致；`wfc doctor` 会检查 `csv_folder` 是否和整合配置相符。

### 3.3 `watch` 用「全量重拉」而不是「追加」

WeClone 的 CSV 片段命名是 `<会话>_<起>_<止>.csv`，靠序号排序合并。
如果追加写入，序号会与文件名冲突，或者需要改写已有文件 —— 两种都容易产生
「一半旧数据 + 一半新数据」的脏状态。

所以 `wfc watch` 的策略是：收到推送 → 等安静期（默认 20s）→ 对变化的会话
**整份重拉**。个人微信的数据量下代价很小，换来的是「任何时刻数据集都是一致的」。

### 3.4 默认明文存储

WeClone 默认 `storage_mode: encrypted`，需要先 `security-init` 设密码。
而 WeFlow 导出的是明文，整合层再引入一层密码流程会让「第一次跑通」变难。

因此 `wfc init` 默认 `plaintext`，并在 README 与 `docs/06-常见问题.md` 里
说明如何切到 `encrypted`。

### 3.5 整合层零第三方依赖

`weflow_clone` 只用标准库（`urllib` / `csv` / `json` / `http.server`）。
好处：

* 在没装 torch 的机器上就能验证整条数据链路；
* 集成测试可以真的起一个 HTTP 服务来跑，不需要 mock 库；
* 迁移到训练机时，只要 Python 就能先 `wfc pull`。

## 4. 失败模式与对应处理

| 环节 | 失败表现 | 处理 |
| --- | --- | --- |
| WeFlow 没开 | `URLError(ConnectionRefused)` | 转成「请确认 WeFlow 正在运行，并在设置 → API 服务启用」 |
| Token 错 | HTTP 401 | 转成「Token 缺失或错误」，附填写位置 |
| 单页过大超时 | `socket.timeout` | 重试 + 提示调大 `timeout_seconds` / 调小 `page_size` |
| 某个会话拉失败 | 客户端异常 | 记入 `summary.failures`，其它会话继续 |
| 某个媒体下载失败 | `copy_or_download_media` 异常 | 记空 `src`，不中断（WeClone 会把该消息降级为截断点） |
| 数据集不合法 | 校验失败 | `wfc prepare` 直接列出「哪一行、什么问题、怎么改」 |
| 训练依赖缺失 | `check_dependencies` | `wfc train` 提前拦截，而不是跑到一半报 ImportError |

## 5. 可观测性

* 每个命令都有「做了什么 → 结果如何 → 下一步是什么」三段式输出；
* `wfc status --json` 给脚本用；
* `wfc doctor` 是唯一需要看的「健康页」；
* 数据集问题集中在 `wfc prepare`，不散落在训练日志里。
